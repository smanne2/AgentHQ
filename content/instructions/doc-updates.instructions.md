# Documentation Updates

- **Docs change with the code** — if you change behavior, a CLI flag, an API, or a
  config option, update the doc that describes it in the same change.
- **Keep examples runnable** — verify commands in docs against the actual CLI/code.
- **Changelog**: add an entry for user-visible changes (new feature, fix, breaking).
- **Stale docs are bugs** — if a page is now wrong, fix it or flag it; don't leave
  a misleading page behind.
- Prefer short, scannable sections; cite the file/flag a doc describes so it stays honest.
