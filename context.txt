1. WHAT THIS PROJECT IS
-----------------------
Agent HQ: a centralized MCP server (Python) that is the single source of truth
for how coding agents behave — roles, instructions, skills, standardized
workflows, stack conventions. Any MCP client (VS Code Copilot, Cline, Claude
Desktop) connects and pulls exactly the guidance its project needs.
Consistency mechanism: pull-based "bootstrap handshake" (MCP cannot inject
into system prompts) — every project ships an AGENTS.md stub that orders the
agent to call agent_hq.bootstrap first, then follow the returned workflow.

Authoritative docs: documents/initial-plan/  (plan.md = what/when,
technical.md = why/how, tracking.md = live status). Read those for details;
this file only carries the short-form handoff.

3. DECISIONS & WHY (full rationale in technical.md §6)
------------------------------------------------------
D1 Python ≥3.11 + uv workspace, official `mcp` SDK (FastMCP), pydantic v2.
   WHY: user maintainability (explicit user decision, 2026-09-24). TS was
   technically equally viable (reference SDK + zod) but set aside. Bonus:
   .gitignore in this repo was already the Python template.
D2 stdio transport v1 (mcp.json per client). WHY: zero infra, all target
   clients support it. Streamable-HTTP is a v2 add; SDK usage is isolated to
   transport/stdio.py + tools/registry.py so the swap is cheap (DD10: pin the
   mcp SDK version — its API churns).
D3 Build in THIS workspace (was named "special-telegram"). Suggest renaming
   the GitHub repo to agent-hq. Monorepo: server+cli+content in one git repo;
   content can be split into its own repo later via AGENT_HQ_CONTENT path.
D4 First validation clients: VS Code + Cline (Claude Desktop second).
D5 Seed content = curated awesome-copilot imports (MIT) + original writes.
D6 Naming: server package agent-hq-server, CLI package agent-hq.
DD5 Conventions are instructions: same schema, own directory + stack tag —
   one fewer type, zero capability loss.
300-LINE RULE = SOURCE FILES ONLY (user clarified). Documents/content exempt.
   Enforced by server/scripts/check_lines.py in CI (ruff has no line-count
   rule — hence the custom script).


4. LEARNINGS & GOTCHAS (hard-won; do not rediscover)
----------------------------------------------------
- awesome-copilot applyTo comes as a SINGLE STRING that may be
  COMMA-SEPARATED (e.g. astro: '**/*.astro, **/*.ts, ...'). Normalization:
  str → split on ","; list → as-is. Also the YAML key is camelCase "applyTo"
  while our field is apply_to → needs pydantic alias + populate_by_name.
  (This was a real bug: without the alias the key silently landed in extras
  and matching quietly did nothing.)
- Pydantic v2: field named `model` is fine if you set
  protected_namespaces=() in model_config — role agents use `model:`.
- Tolerant imports: extra="allow" on all frontmatter models so unknown
  future keys never break the index (risk R3). Bad files must become Issues,
  never exceptions — catalog.load() catches everything.
- pyright (npx) cannot see .venv unless pyrightconfig.json sets
  "venvPath": "." + "venv": ".venv". Without it, unresolved imports report as
  errors AND mask the real type errors (we saw 27 fake → 16 real).
- ruff B009 forbids getattr(obj, "const") while pyright rejects direct attr
  access on pydantic extras → use model.model_extra (dict | None) in tests.
- uv: `uv sync` from the workspace root syncs all members (server+cli) into
  one .venv. System python here is 3.9 — uv auto-provisions managed CPython.
- pathspec (gitwildmatch) is the glob engine for applyTo matching; build one
  PathSpec per instruction's glob list, test each project file path.
- Agent-written files can be clobbered by an editor auto-saving a stale
  buffer (happened to plan.md once — my write landed, editor reverted it).
  Fix: commit work promptly; untracked files are the vulnerable ones.
- Awesome-copilot's own `workflows/` dir holds repo-ops reports, NOT dev
  processes → our phased workflow type (phases/checklists/gates) is original;
  nothing upstream defines it.
- uv 0.12.x: bare `uv sync` does NOT install workspace members when the root
  project has `[tool.uv] package = false` — it even UNINSTALLS previously
  installed members (pytest then fails with ModuleNotFoundError for
  agent_hq_server). Use `uv sync --all-packages` (CI already does this;
  the cheat-sheet below was fixed to match).
- mcp SDK 1.30.0 (pinned since Phase 0): calling tools/call with an unknown
  tool name returns a TOOL-level error — result content "Unknown tool: ...",
  isError=true — NOT a JSON-RPC protocol error. Older SDKs returned a
  JSON-RPC error; the 2026-09-26 stdio test asserted the old shape and was
  red on 1.30. Test renamed to *_is_tool_error.
- Python type-level module `textio` (used for TextIOBase in type stubs) is
  NOT importable at runtime — pyright flags `import textio` as unresolved.
  Use `typing.IO[str]` (or `io.TextIOBase`) instead.
- pyright needs a node runtime: `npx pyright`/`npx pyright` only works where
  node exists. Fallback that works in this sandbox: `uvx pyright` (uses the
  repo pyrightconfig.json, 0 errors as of 2026-10-05).
- graphify CLI (managed CPython 3.10) intermittently dies with
  "ModuleNotFoundError: No module named 'encodings'" — a retry succeeds.
  graphify-out/graph.json is built per commit; after code changes run
  `graphify update .` (no API cost). Disambiguate explain targets as
  `path::Symbol` when a name matches nodes in multiple files.

6. COMMAND CHEAT-SHEET
----------------------

                                            # does NOT install the server/cli members!)
  uv run pytest                             # tests (48)
  uv run ruff check . && uv run ruff format --check .
  uvx pyright                               # type check (uses pyrightconfig.json;
                                            # `npx pyright` where node exists)
  uv run python server/scripts/check_lines.py
  uv run agent-hq-server                    # MCP server over stdio
  uv run agent-hq version                   # CLI entry
  graphify update .                         # refresh the repo graph after code changes
